# myukit.com (뮤킷) 사이트 전체 기능 분석

- 분석일: 2026-08-31
- 도구: Playwright MCP 실브라우저 렌더링 (로그인 없이 접근 가능한 범위)
- 스크린샷: `docs/screenshots/myukit-*.png`

## ⚠️ 데이터 추출(크롤링) 가능성 결론부터: **권장하지 않음**

1. **robots.txt에 ClaudeBot이 명시적으로 차단되어 있음**
   ```
   User-agent: ClaudeBot
   Disallow: /
   ```
   같은 방식으로 GPTBot, Google-Extended, CCBot, Bytespider, Amazonbot, Applebot-Extended, meta-externalagent, CloudflareBrowserRenderingCrawler도 전부 차단.
2. **Content-Signal 헤더로 AI 학습 목적 이용을 명시적으로 거부**
   ```
   Content-Signal: search=yes, ai-train=no, use=reference
   ```
   → 검색엔진 색인은 허용하지만 AI 학습/자동 수집은 명시적으로 "no".
3. `/my`, `/my/*`, `/login`, `/notices`, `/yeonmyu-calendar`, `/search` 등도 일반 크롤러(`User-agent: *`)에게 차단되어 있음. `/plays`, `/plays/{id}`, `/today` 같은 핵심 데이터 페이지는 일반 크롤러엔 열려 있지만, AI 크롤러는 사이트 전체가 차단.
4. **서비스가 이미 종료 수순** (`docs/01-...` 참고 아님, 아래 별도 항목) — 데이터 신선도 자체가 낮아짐.

→ 이번 분석은 "브라우저로 직접 열람해 기능/구조를 파악"하는 수준에서 마쳤고, **정기적/자동화된 데이터 수집 파이프라인은 만들지 않는 것을 권고**합니다. 이 사이트의 핵심 데이터(원천은 결국 KOPIS + 자체 수작업 큐레이션)는 KOPIS 오픈API와 자체 커뮤니티 운영으로 대체 확보하는 방향이 맞습니다.

## 0. 서비스 상태 — ⚠️ 종료 수순 (중요)

- 홈 상단에 공지: **"📢 서비스 종료 안내 (2026.07)"**
- `/notices/12` 원문 요약:
  - **서비스 종료일: 2026년 7월 26일** (운영상의 사유)
  - 2026.06부터 일부 기능 중단: 신규 공연 등록 문의, 원캐스트 등록 문의, 당일/현장 할인 이벤트 등록
  - 종료일까지는 스케줄/이벤트 업데이트 정상 제공 예정이라고 안내했었음
  - '내 달력'에 등록한 일정은 희망자에 한해 엑셀로 백업 제공 (구글폼 신청)
  - 종료 후 회원 정보·데이터 전량 폐기 예정
- **오늘(2026-08-31)은 안내된 종료일(2026-07-26)로부터 이미 5주 이상 지난 시점인데 사이트는 여전히 접속됨.** 다만 `/today`(오늘의 공연) 실측 결과 2026-08-31 하루 공연이 단 2건만 표시됨 — 실제 국내 공연 시장 규모에 비해 명백히 적은 수치로, **업데이트가 사실상 멈췄거나 큐레이션 범위가 대폭 축소된 상태**로 추정됨.
- 시사점: 작은 팀(1인~소수)이 수작업으로 캐스팅 로테이션을 입력하는 구조였을 가능성이 높고, 그 운영 부담이 서비스 종료의 원인으로 보임 — 이 프로젝트를 기획할 때 "수작업 큐레이션 의존도"를 낮추는 설계가 중요한 교훈.

## 2. 오늘의 공연 (`/today`)

- 날짜 선택기(기본값: 오늘)
- **필터**: 위치(대학로/수도권/수도권 외/전체), 공연장 규모(중소극장/대극장 800석 이상/전체)
- 로그인 시 "관심 있는 공연만 모아보기" 개인화 필터 제공 (비로그인은 잠김)
- 결과 테이블: 시간대별 그룹핑 → 공연명(링크) + **그날의 실제 캐스팅 배우 목록**을 한 줄로 표시
- 특정 회차에 "스페셜 커튼콜" 같은 이벤트가 있으면 관련 SNS(X) 링크를 별도로 노출
- 광고: Taboola 아웃스트림 비디오, Popin 네이티브 광고 삽입 — 연뮤덕보다 광고 밀도가 훨씬 높음

## 3. 공연 상세 (`/plays/{id}`) — 가장 독자적인 기능

예시: `/plays/1537` (뮤지컬 〈룰렛〉)

1. 헤더: 작품명, 공연 기간, 공연장(네이버 지도 링크), 찜하기(관심 공연 담기) 버튼
2. **역할별 캐스팅 표**: 배역명 → 그 배역을 맡은 배우 전원 나열 (예: "포우" 역 - 심수호/도정연/박상준)
3. **일자별 캐스팅 로테이션 캘린더** (핵심 차별 기능):
   - 월별 달력 뷰, 날짜 칸마다 회차 시간(16:00/20:00 등)과 **그 회차에 실제 출연하는 배우 전원의 조합**을 표시
   - 특정 날짜에 "❗" 아이콘 — 캐스팅 변경/대역 등 특이사항 표시로 추정
   - 뷰 전환: 달력/목록, 캐스팅/회차 보기 토글
   - **이 정보는 KOPIS API의 `prfcast`(전체 출연진 나열)로는 얻을 수 없는 정보**임 — KOPIS는 "이 공연에 출연하는 배우 명단"만 제공하고 "이 날짜 이 회차에 누가 나오는지"는 제공하지 않음. 즉 이 부분은 뮤킷이 수작업(또는 팬 제보/공식 SNS 모니터링)으로 직접 구축한 고유 데이터로 판단됨.

## 4. 전체 공연 보기 (`/plays`)

- 필터: 상태(진행중/예정 토글), 정렬(개막일순), 위치(전체), 규모(전체)
- "진행 중" 필터 기준 **32개 공연**만 노출 → KOPIS 전체 DB(수천 건) 대비 극히 일부만 다루는 **수작업 큐레이션 방식**임을 확인 (대극장/중대형 뮤지컬·연극 위주, 소규모 대학로 공연도 일부 포함하되 전수는 아님)
- 각 항목: 작품명, "N일 후 종료"/"오늘 종료" 배지, 공연장(네이버 지도 or 나무위키/더뮤지컬 링크), 공연 기간

## 5. 연뮤 달력 (`/yeonmyu-calendar`) — UGC 이벤트 캘린더

- 안내 문구: **"이용자들이 직접 등록하는 스케줄이 공유되는 달력입니다"**
- 뷰: 달력 / 목록 / **스케줄 만들기**(`/yeonmyu-calendar/add`) — 누구나(로그인 시) 이벤트를 등록해 전체 공유 가능
- 실측 데이터: "온 20:00 해몽가", "콘 18:00 STAGE CONCERT SERIES Ⅰ..." 등 정규 공연 회차가 아닌 **팬미팅/콘서트/스페셜 이벤트성 일정** 위주로 등록되어 있음 (아이콘 "온"=온라인 이벤트, "콘"=콘서트로 추정)
- robots.txt에서 `/yeonmyu-calendar`는 명시적으로 크롤링 차단됨

## 6. 로그인 (`/login`)

- 카카오 로그인, 구글 로그인만 제공 (`/oauth/kakao/authorize`, `/oauth/google/authorize`)
- 이메일 회원가입 옵션 없음 → 소셜 로그인 전용 구조

## 7. 기술적 관찰

- 프론트엔드: 서버 렌더링 + `cdn2.myukit.com`에서 정적 자산 서빙, `fullcalendar.js` 라이브러리로 캘린더 UI 구현
- Cloudflare 사용 (robots.txt에 "Cloudflare Managed content" 블록 존재, `/cdn-cgi/rum` 빔 전송)
- 별도의 공개 데이터 API 엔드포인트는 관측되지 않음 (서버사이드 렌더링된 HTML에 데이터가 이미 포함되는 방식으로 보임 — 네트워크 탭에서 별도 JSON API 호출이 잡히지 않음)
- 콘솔 에러 다수: CORS 폰트 로드 실패, `manifest.json`/`favicon.ico` 404 — 유지보수가 느슨해진 정황(서비스 종료 수순과 일치)

## 종합 시사점 (연뮤덕과 비교)

| 항목 | 연뮤덕 | 뮤킷 |
|---|---|---|
| 상태 | 정상 운영 중 | **종료 수순, 업데이트 사실상 중단 추정** |
| 데이터 원천 | KOPIS 명시 | 불명시, KOPIS + 수작업 추정 |
| 커버리지 | KOPIS 기반 폭넓은 자동 수집 | 32개 내외 수작업 큐레이션 (대극장 중심) |
| 고유 기능 | 배우별 출연작 필터, 다중 예매처 링크, 용어사전 | **일자별 캐스팅 로테이션 달력(회차별 정확한 캐스팅)**, 애배(관심 배우) 팔로우, UGC 이벤트 캘린더 |
| 광고 밀도 | 낮음 | 매우 높음 (Taboola, Popin) |
| robots.txt | (미확인, 별도 조사 필요) | **ClaudeBot 등 AI 크롤러 전면 차단 + ai-train=no** |

**가장 중요한 인사이트**: "일자별/회차별 정확한 캐스팅 로테이션"은 뮤지컬 팬덤이 가장 원하는 정보인데, KOPIS 오픈API로는 채울 수 없는 영역이다. 이 데이터를 확보하려면 (a) 수작업 큐레이션(뮤킷처럼 운영 부담 큼, 결국 종료로 이어짐), (b) 팬/제작사 공식 SNS 모니터링 자동화, (c) 사용자 제보(크라우드소싱) 중 하나를 택해야 하며, 이 선택이 서비스의 지속가능성을 좌우할 핵심 설계 결정이 될 것으로 보인다.
